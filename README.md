# 矩阵折叠密室（Matrix Folding Chamber）

一个以 **2×2 线性变换** 为核心机制的 2D 解谜游戏。玩家从手牌中打出矩阵卡，让钥匙在当前空间中旋转、剪切、镜像或投影，在有限步数内把钥匙送到锁上，同时避开红色禁区。

项目完全运行在浏览器端（Vite + TypeScript + Canvas 2D + KaTeX），可选接入任意 OpenAI 兼容接口提供「AI 提示」，并附带一个零依赖的 Node 静态托管 / API 适配服务，可直接部署到 Render 等 PaaS 平台。

## 核心玩法

1. 画布中有一把**钥匙**（随矩阵变换）和一把**锁**（固定不动）。
2. 每张手牌是一个 2×2 矩阵，打出后立即作用于整个空间：
   - `M = A_k · … · A_1`，**后打出的卡在左侧**（左乘）；
   - 几何意义是「先应用先打出的卡，再应用后打出的卡」。
3. 目标：让钥匙与锁的距离小于 `0.15`。
4. 失败条件：
   - 钥匙落入红色**禁区**（立即失败）；
   - 累积矩阵**不可逆**（`det(M) = 0`，投影后空间被压扁，立即失败）；
   - **步数超限**。
5. 支持**撤销 / 重置**；撤销会返还卡牌次数，并重新判定（可从终局回退）。

每张预设卡消耗 1 步，自定义矩阵卡消耗 2 步。界面会持续展示最近 5 步的操作栈公式，例如：

```text
M = R · S · v⃗
```

### 卡牌库

| 卡牌 | 矩阵 | 符号 | 效果 |
| --- | --- | --- | --- |
| 旋转 90° | `[[0, -1], [1, 0]]` | `R` | 逆时针旋转 90° |
| 水平剪切 | `[[1, 1], [0, 1]]` | `S` | `x' = x + y`，`y' = y` |
| X 轴投影 | `[[1, 0], [0, 0]]` | `P` | 把整个平面压到 X 轴，不可逆 |
| X 轴镜像 | `[[1, 0], [0, -1]]` | `M` | 沿 X 轴翻转 |

来源：[cards.ts](src/game/cards.ts)

## 功能特性

- **纯函数游戏内核**：矩阵运算、判定、状态推进与渲染完全解耦，便于测试与验证。
- **动态几何可视化**：网格、坐标轴、刻度与钥匙本体都随矩阵变换；钥匙在剪切时会真实形变。
- **双重坐标参考**：灰色虚线为固定参考系，彩色坐标轴随 `M` 变换，便于理解「空间被折叠」。
- **动画与判定分离**：逻辑立即结算，画面用 300ms 插值过渡；动画期间冻结输入，避免连点重复结算。
- **BFS 可解性保证**：随机关卡通过 BFS 校准，`maxSteps` 恰好等于最少步数。
- **AI 提示（可选）**：OpenAI 兼容接口，3 秒超时、失败重试一次、本地无感回退，绝不阻塞游戏。
- **矩阵工坊**：自由输入 2×2 矩阵，实时预览公式、`det` 警告与空间虚影。
- **演示模式**：约 90 秒自动演示核心玩法，可随时中断。
- **内置测试**：14 个断言覆盖矩阵、判定、撤销、BFS、生成器、提示清洗与演示脚本结构。

## 数学约定与判定规则

### 矩阵与向量

- 点用**列向量**表示，变换为 `p' = M · p`。
- 矩阵乘法 `multiply(A, B)` 表示「先应用 `B`，再应用 `A`」。
- 出牌顺序：`M = A_k · … · A_1`，先打出的卡位于乘法链最右侧。

### 判定顺序

判定函数 `evaluate` 的顺序是固定的（见 [judge.ts](src/game/judge.ts)）：

1. **禁区**：钥匙落点进入任一禁区 → `lost / forbidden`（返回禁区下标用于高亮）。
2. **胜利**：`dist(key, lock) < 0.15` → `won`。
3. **投影**：`|det(M)| ≤ 1e-9` → `lost / projection`。
4. **步数**：`stepsUsed > maxSteps` → `lost / steps`。

> 胜利先于投影与步数检查：投影卡恰好把钥匙压到锁上、或最后一步压线到达，都算赢。

### 固定对象与变换对象

| 对象 | 是否随 `M` 变换 | 说明 |
| --- | --- | --- |
| 钥匙 | 是 | 形状本身也随矩阵形变（剪切/缩放可见） |
| 锁 | 否 | 固定世界坐标 |
| 禁区 | 否 | 轴对齐矩形，固定世界坐标 |
| 固定参考坐标系 | 否 | 灰色虚线，带数字刻度 |
| 彩色坐标轴 / 网格 | 是 | 直观展示线性映射 |

### 关键常量

| 常量 | 值 | 位置 |
| --- | --- | --- |
| 胜利阈值 | `0.15` | [judge.ts](src/game/judge.ts) |
| 可逆性阈值 | `1e-9` | [matrix.ts](src/game/matrix.ts) |
| 动画时长 | `300ms` | [main.ts](src/main.ts) |
| 公式刷新去抖 | `100ms` | [main.ts](src/main.ts) |

## 关卡系统

### 内置关卡

| # | 关卡 | 目标 | 步数 | 设计意图 |
| --- | --- | --- | --- | --- |
| 1 | 第一关：旋转开门 | `[2,2] → [-2,2]` | 1 | 熟悉旋转与钥匙变换 |
| 2 | 第二关：剪切对齐 | `[0,2] → [4,2]` | 2 | 理解剪切对坐标的影响 |
| 3 | 第三关：先剪后转 | `[2,1] → [-1,3]` | 2 | 出牌顺序陷阱：反序会撞进禁区 |
| — | 矩阵工坊（沙盒） | `[2,1] → [-2,2]` | 12 | 自由实验，不保证可解 |

内置关卡位于 [src/levels](src/levels)，通过 `loadLevel()` 解析 `cardId` 与次数。主线 3 关全部通关后解锁「矩阵工坊」。

### 关卡 JSON 格式

```json
{
  "id": "level-3",
  "name": "第三关：先剪后转",
  "key": [2, 1],
  "lock": [-1, 3],
  "forbidden": [{ "x": 0.5, "y": 1.5, "w": 1, "h": 1 }],
  "maxSteps": 2,
  "deck": [
    { "cardId": "shearX", "uses": 1 },
    { "cardId": "rotate90", "uses": 1 }
  ]
}
```

字段说明：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` / `name` | `string` | 必填 |
| `key` / `lock` | `[number, number]` | 世界坐标 |
| `forbidden` | 矩形数组 | 最多 3 个，`w/h > 0`，坐标绝对值 ≤ 10 |
| `maxSteps` | `integer` | `1 ~ 10` |
| `deck` | `{cardId, uses}[]` | `1 ~ 5` 张；`uses` 为 `1 ~ 3` 的整数；`cardId` 必须在卡牌库中 |

Schema 校验见 [validate.ts](src/game/validate.ts)，加载器会在遇到未知卡牌或非法次数时直接抛错。

### 新增关卡

1. 在 [src/levels](src/levels) 下新增 JSON（或直接扩展数组）。
2. 在 [main.ts](src/main.ts) 的 `levels` 数组与 `MAIN_LEVELS` 中登记。
3. 建议用 `bfsMinSteps()` 验证「最少步数 = `maxSteps`」，并补充到 [tests.ts](src/game/tests.ts) 的测试中。

## 随机关卡生成器

实现见 [generator.ts](src/game/generator.ts)。生成流程：

1. 按难度随机抽卡组，并随机分配每张卡的可用次数。
2. 随机挑一个初始钥匙坐标（`[-3, 3]`，排除原点）。
3. 抽一条**遵守次数限制的合法出牌序列**，得到终点并作为锁的位置。
4. 丢弃中途出现不可逆矩阵、坐标越界（`|x|,|y| > 8`）、钥匙与锁重合的候选。
5. 把禁区放在「错误顺序会到达、正确路径不会经过」的位置，制造顺序陷阱。
6. 用 **BFS 求最少步数**；只有 `minSteps` 落在难度区间且 `maxSteps = minSteps` 时才接受。
7. 最多尝试 150 次；极端情况下回退到预置演练关，绝不抛错。

### 难度规则

| 难度 | 步数区间 | 卡牌数 | 每张次数 | 禁区数 |
| --- | --- | --- | --- | --- |
| 简单 | 1 ~ 2 | 2 | 1 | 0 ~ 1 |
| 普通 | 2 ~ 3 | 2 ~ 3 | 1 ~ 2 | 1 |
| 困难 | 3 ~ 5 | 3 ~ 4 | 1 ~ 2 | 2 |

> 生成器保证关卡**一定可解**，且 `maxSteps` 恰好等于最少步数（不多不少）。随机关卡会追加到关卡列表末尾，可通过「上一关」返回。

## AI 提示

AI 仅用于生成**一句 30 字以内的启发式提示**，不参与关卡生成或实时判定（随机关卡已改为本地生成器）。

### 调用链

```text
点击「AI 提示」
   │
   ▼
getHint({levelId, name, reason})
   │  POST /api/ai  {scene:'hint', system, payload}
   ▼
server.mjs ──► OpenAI 兼容 /chat/completions（20s 上游超时）
   │
   ▼
前端：3s 超时、失败重试 1 次、sanitizeHint
   │  ├─ 合格（单行、1~30 字）→ 显示
   │  └─ 失败 / 不合格 → pickFallbackHint(reason) 本地提示
```

- 前端超时 3 秒，最多尝试 2 次；仍失败则静默回退，`getHint` 永不 reject。
- `sanitizeHint` 会去掉首尾引号、拒绝换行与超过 30 字的文本。
- 后端未配置 `AI_API_KEY` 时返回 `503`，前端直接使用本地提示。
- 本地提示按失败原因（`forbidden` / `steps` / `projection`）匹配，其余随机给通用思路。见 [fallback.ts](src/ai/fallback.ts)。

### 后端接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/ai` | 请求体 `{scene: "hint" \| "level", system, payload}`，返回 `{content}` |
| `GET` | `/api/health` | 返回 `{ok, model, keyConfigured}` |
| `GET` | `/*` | 托管 `dist/`；无扩展名路径回退 `index.html`（SPA） |

后端参数：`level` 场景 `max_tokens=800 / temperature=1`，`hint` 场景 `max_tokens=64 / temperature=0.6`；请求体上限 64 KB，上游超时 20 秒。静态文件做了路径穿越防护。

## 矩阵工坊

通关全部主线关卡后解锁（按钮才会显示）。工坊基于沙盒关卡运行：

- 4 个输入框接受 `[-2, 2]` 内的数字，非法输入会标红并禁用「打出」。
- 实时预览：
  - 当前输入的矩阵公式（KaTeX）；
  - 若为零矩阵：提示「整个空间被压成一个点」；
  - 若 `det = 0`：提示「不可逆，空间会被压扁」；
  - 画布上叠加空间虚影与钥匙落点虚影。
- 快捷按钮：单位矩阵、旋转 90°、水平剪切、投影、清零。
- 自定义矩阵固定消耗 **2 步**，不占用预设卡次数；撤销时不返还次数。
- 不保证沙盒关卡可解，工坊本身即实验场。

点击「演示模式」启动约 90 秒的自动脚本（[demo.ts](src/demo.ts)），依次展示：

覆盖范围（共 14 项）：

1. 旋转 90° 四次回到原点；
2. 剪切坐标计算；
3. `det = 0` 不可逆；
4. 撤销恢复矩阵、步数与次数；
5. 胜利判定；
6. 次数用完禁止再出；
7. 投影后判负；
8. 固定禁区 + 出牌顺序（反序失败 / 正序通关）；
9. 自定义矩阵消耗 2 步且可撤销；
10. 预置回退关全部通过 Schema + BFS 校验；
11. 非法关卡被正确拒绝；
12. 提示清洗（单行、30 字内）；
13. 演示脚本结构与时长；
14. 随机关卡各难度可解且落在难度区间。

> 因为测试是静态导入的副作用代码，生产构建中也会执行（仅在控制台输出，不影响玩法）。

运行方式：

```bash
npm run dev
# 打开 http://localhost:5173，按 F12 查看 Console
```

## 生产服务与部署

`server.mjs` 仅使用 Node 内置模块（`node:http`、`node:fs`、`node:path`），无需安装生产依赖。

### 本地生产运行

```bash
npm install
npm run build
npm run serve
```

### Render 等 PaaS

| 配置项 | 建议值 |
| --- | --- |
| Build Command | `npm install && npm run build` |
| Start Command | `npm run serve` |
| 环境变量 | `AI_API_KEY`（可选）、`AI_BASE_URL`、`AI_MODEL` |
| 端口 | 平台通过 `PORT` 注入；服务监听 `0.0.0.0` |

注意事项：

- `dist/` 已被 `.gitignore` 忽略，部署时必须先构建。
- 未配置 `AI_API_KEY` 时游戏仍可完整游玩，仅 AI 提示使用本地文案。
- 健康检查可用 `GET /api/health`。

## 设计取舍与已知限制

- **逻辑与动画分离**：出牌瞬间完成逻辑结算，画面只做 300ms 插值；动画期间冻结按钮，避免重复结算与状态错乱。
- **判定与 BFS 顺序保持一致**：禁区 → 胜利 → 不可逆 → 步数，确保「生成器认为可解」与「实际判定」一致。
- **AI 不接触游戏状态**：提示接口只接收关卡 id/名称与失败原因，避免模型影响实时逻辑；任何失败都本地回退。
- **固定画布 800×600**：世界范围约 `±10` 单位，尚未做移动端/响应式适配。
- **无持久化**：通关进度（`beaten`）与随机关卡仅保存在当前页面内存，刷新后重置。
- **工坊不保证可解**：沙盒允许输入零矩阵或任意组合，失败是预期体验的一部分。
- **随机关卡会累积**：每次生成都会追加到 `levels` 数组，长时间游玩后关卡列表会变长。
- **测试无独立命令**：测试依赖页面加载执行，尚未接入 CI 或 `npm test`。
- **服务端 `level` 场景保留**：后端仍支持 `scene: "level"`（更多 token），但前端目前已改用本地随机关卡生成器。
